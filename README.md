# 早押しクイズ盤(Firebase 版)セットアップ手順書

claude.ai のアカウントがなくても、リンクを開くだけで参加できる版です。
Firebase(データの置き場所)と GitHub Pages(ページの公開場所)を、どちらも無料の範囲で使います。

> Firebase や GitHub の画面の表記は、変更されていることがあります。見当たらないときは似た名前のメニューを探してください。

---

## 0. 入っているファイル

| ファイル | 役割 |
|---|---|
| `index.html` | ページ本体 |
| `style.css` | デザイン |
| `app.js` | 動き(早押し判定、タイマー、質問の記録など) |
| `firebase-config.js` | **あなたの Firebase の設定値を書き込むファイル** |
| `database.rules.json` | データベースの守り(誰が何を読み書きできるか) |
| `README.md` | この手順書 |

---

## 1. Firebase のプロジェクトを作る

1. Google アカウントで https://console.firebase.google.com を開く
2. 「プロジェクトを追加(作成)」を押し、好きな名前を付ける(例:`hayaoshi-quiz`)
3. Google アナリティクスは使わないのでオフで構いません

## 2. 匿名ログインを有効にする

参加者がアカウント登録なしで入れるようにする設定です。

1. 左メニューの「Authentication」→「始める」
2. 「ログイン方法(Sign-in method)」タブ →「匿名」を選んで **有効** にし、保存

## 3. Realtime Database を作る

1. 左メニューの「Realtime Database」→「データベースを作成」
2. ロケーションは **シンガポール(asia-southeast1)** がおすすめです(日本から近い)
3. セキュリティルールは **「ロックモードで開始」** を選ぶ
4. 作成されたら「ルール」タブを開き、中身をすべて消して、`database.rules.json` の中身を丸ごと貼り付け →「公開」

> ルールを貼り忘れると、部屋が作れない・ボタンが押せない状態になります。

## 4. 設定値を書き込む

1. 左上の歯車 →「プロジェクトの設定」
2. 下のほうの「マイアプリ」でウェブアイコン(`</>`)を押し、アプリ名を付けて登録(Firebase Hosting のチェックは不要)
3. 表示される `firebaseConfig = { ... }` の各値を、`firebase-config.js` の「ここに〜」の部分に貼り付ける
4. **`databaseURL` があるか確認**してください。ない場合は、Realtime Database の画面上部に出ている URL(`https://〜.firebasedatabase.app` のような形)を貼ります

> この設定値は公開されても大丈夫な種類のものです。データの守りは手順 3 のルールが担当します。

## 5. 手元で試す(任意)

`index.html` をダブルクリックで開いても動きません(ブラウザの制限のため)。試すときは、このフォルダでターミナルを開いて

```
python -m http.server 8000
```

を実行し、ブラウザで `http://localhost:8000` を開きます。

## 6. GitHub Pages で公開する

1. https://github.com でアカウントを作り、右上の「+」→「New repository」
2. 名前を付けて(例:`hayaoshi`)**Public** で作成
3. 「Add file」→「Upload files」で、6つのファイルをすべてアップロードして「Commit changes」
4. リポジトリの「Settings」→ 左の「Pages」→「Source」を **Deploy from a branch**、ブランチを **main**、フォルダを **/(root)** にして「Save」
5. 数分待つと、`https://あなたのユーザー名.github.io/hayaoshi/` のような URL で公開されます

## 7. 公開先のドメインを Firebase に登録する(念のため)

1. Firebase の「Authentication」→「設定」タブ →「承認済みドメイン」
2. 「ドメインを追加」で `あなたのユーザー名.github.io` を追加

## 遊び方

### 司会
1. 公開した URL を開き、「司会として部屋を作る」を押す
2. 「招待リンクをコピー」で友達にリンクを送る(部屋コードを口頭で伝えても入れます)
3. 「問題の登録」で問題文と答えを登録しておく
4. 「この問題で開始」→ 質問タイム → 時間切れで自動的に早押しタイム
5. 押した人の答えを聞いて ○ か ×。○ か「答えを発表して終了」で、問題文と答えが全員に公開されます

### 参加者
1. 送られてきたリンクを開く(アカウント不要)
2. 名前を入れて「参加」
3. 質問タイムは質問欄に書き込み、早押しタイムでボタンを押す

---

## 注意点

- **司会は、部屋を作ったのと同じ端末・同じブラウザで操作してください。** 匿名ログインはブラウザごとに別人扱いになるため、別のブラウザやシークレットモード、閲覧データの削除をすると司会の権限と登録した問題が使えなくなります。
- 問題文と答えは、司会本人しか読めない場所に保存されます。参加者には ○ か「答えを発表して終了」を押すまで届きません。
- 早押しの順番はサーバーに先に届いた人が勝ちです。通信の速さの差は残るので、コンマ数秒を争う勝負には向きません。
- リンク(部屋コード)を知っている人は誰でも入れます。知らない人に広めないでください。参加者を退出させる機能はありません。
- 無料プラン(Spark)の上限や条件は変わることがあります。使う前に Firebase の公式の料金ページで確認してください。友達数人で遊ぶ程度なら、通常は無料の範囲に収まる想定です。

## うまくいかないとき

| 症状 | 確認すること |
|---|---|
| 「設定値がまだ入っていません」と出る | `firebase-config.js` を書き換えて、もう一度アップロードしたか |
| 「匿名ログインに失敗しました」 | 手順 2 で匿名ログインを有効にしたか |
| 部屋が作れない・ボタンが押せない | 手順 3 でルールを貼り付けて「公開」したか |
| 何も表示されない | `databaseURL` が入っているか。ブラウザの開発者ツールのコンソールにエラーが出ていないか |
| 公開 URL が 404 | GitHub Pages の設定後、数分待ったか。ファイルがリポジトリの一番上の階層にあるか |
